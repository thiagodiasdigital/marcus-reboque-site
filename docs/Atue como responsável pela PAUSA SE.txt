Atue como responsável pela PAUSA SEGURA E CONTINUIDADE OPERACIONAL do projeto Marcus Reboque.

O usuário precisa desligar o computador agora.

Sua missão não é continuar desenvolvendo o site. Sua missão é congelar o estado atual do projeto, preservar tudo o que já foi feito e preparar uma retomada inequívoca para a próxima sessão do Codex.

## REGRA PRINCIPAL

PARE toda implementação nova.

Não inicie novas funcionalidades.

Não faça deploy.

Não faça push.

Não configure GitHub, Vercel, DNS ou domínio.

Não libere indexação.

Não descarte, reverta ou sobrescreva nenhuma alteração atual.

Não use `git reset --hard`, `git clean`, checkout destrutivo ou comandos equivalentes.

## 2. NÃO CONTINUAR A TAREFA ATIVA

Se a tarefa de fechamento da homepage V1 estiver em andamento, interrompa-a em um ponto seguro.

Não comece:

* novas correções visuais;
* novas páginas;
* novos testes demorados;
* instalação de navegadores;
* instalação de dependências;
* geração de novo layout;
* deploy.

Preserve todo o trabalho parcial existente.

## 6. PROMPT AUTOMÁTICO DE RETOMADA

Crie:

docs/PROMPT_RETOMADA_CODEX_MARCUS_REBOQUE.md

O conteúdo deve ser um prompt autossuficiente para uma nova sessão do Codex.

Esse prompt deverá instruir a futura sessão a:

1. confirmar que está na raiz correta;
2. ler `AGENTS.md`, caso exista;
3. ler `RETOMAR_AQUI_MARCUS_REBOQUE.md`;
4. ler `docs/CHECKPOINT_PAUSA_MARCUS_REBOQUE.md`;
5. ler os relatórios citados no checkpoint;
6. verificar branch e commit;
7. executar `git status`;
8. confirmar que `.env.local` continua ignorado;
9. confirmar que `NEXT_PUBLIC_INDEXABLE=false`;
10. não refazer trabalho concluído;
11. validar arquivos parcialmente alterados;
12. retomar exatamente a próxima ação registrada;
13. executar lint, typecheck e build no momento apropriado;
14. não fazer deploy ou push sem nova autorização.

O prompt deve diferenciar claramente:

* concluído;
* parcialmente concluído;
* não iniciado;
* bloqueado;
* pendência não bloqueante.

## 8. PRESERVAÇÃO COM GIT

Verifique cuidadosamente o estado do repositório.

### Se houver alterações de código ou documentação não commitadas

1. confirme que nenhum segredo será adicionado;
2. confirme que `.env.local` está ignorado;
3. não adicione artefatos de QA ignorados;
4. não adicione processos, caches, `.next` ou `node_modules`;
5. adicione somente arquivos legítimos do projeto;
6. faça um commit local de checkpoint.

Mensagem:

chore: checkpoint project before shutdown

O commit pode conter trabalho parcial, desde que o checkpoint documente claramente que ainda não está finalizado.

### Se o repositório estiver limpo

Crie e versione somente os arquivos de checkpoint e retomada.

Não crie commit vazio.

## 9. TAG LOCAL DE SEGURANÇA

Após o commit de checkpoint, crie uma tag local anotada com nome baseado na data e hora, por exemplo:

checkpoint-pausa-marcus-reboque-2026-06-18

Caso o nome já exista, acrescente hora e minuto.

Mensagem da tag:

Checkpoint seguro antes do desligamento

Não envie a tag para remoto.
